
===== strategy_exec
VERDICT: With default settings the EXECUTION part reproduces the engine's trades: same arm, same entry bar, same exit bar and same direction. The rounding direction is safe: the entry is floored/ceiled at lim +/- 0.001 tick, the stop is floored for a long and ceiled for a short, and the target is ceiled for a long and floored for a short. This means any emulator fill, stop or target implies the engine event on the same bar. Where the engine and the emulator disagree, the code's fallbacks (missN cancel, Engine-exit close_all) cover what is left. Prices match except in three cases nothing in the code can remove: (a) a gap through the entry, stop or target fills at the open, while the engine books the level; (b) Market mode enters at the next open, while the engine books the signal close; (c) a bar that touches both the stop and the final target. In case (c) the engine always books a loss, but TradingView's O-H-L-C / O-L-H-C path can fill the target, so the result (win or loss) differs on the same exit bar. This is rare at the defaults (the stop and the 2R target are 3R apart), but it cannot be fixed without changing the engine rule; finding 1 adds a counter for it. The exState machine has no stuck path: state 1 always ends in an emulator fill, the engine's evCancel (expired or replaced, including replacement by a ghost), the missN path or a news/force-close cancel; state 2 always has a stop. It does not double-count: exClosed fires once per trade, exPnl collects partials before the close, Rule C is updated once per candle, and the pause/day-block counters are correct. Pine: all functions are defined before use, strategy.* calls inside functions and local blocks are legal, and no local name shadows a global; pynescript parses the whole file OK. Checked and fine: fill-bar stop (the exit placed at the arm is attached, so entry and stop both fill on the fill bar and exClosed runs through the closedNew branch), targets first active on fill+1, stop moves active from the next bar, expiry window A+1..A+5, REPLACED arm and new arm on the same bar (cancel, then re-place), ghost setups, the 5-fill cap (the engine never arms past it, so a fill can never be refused), Market mode on the next bar, sessions and gaps, SMALL_FRAC qty, leverage cap, close_all at the next open followed by re-arming on the cooldown bar, and the force-close / weekend / news cancel paths. The definite defects are in non-default settings: earn-back lets a later engine trade overwrite the exits of the position still open; the order in which partial exits are created can make the partials never fill; and the strategy does not close a position the engine never filled.

int NthSunday(int y, int mon, int n)
{
